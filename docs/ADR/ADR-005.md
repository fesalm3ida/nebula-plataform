# ADR-005

## Título

Modelo de distribuição de conteúdo baseado em Servidores e Endpoints M3U externos.

---

## Status

**Aceito**

---

## Contexto

Inicialmente o domínio da Nebula previa que os dispositivos receberiam acesso a uma ou mais Playlists.

Durante a modelagem do domínio verificou-se que o funcionamento real da operação é diferente.

A Nebula **não gera playlists M3U**.

Os endpoints M3U são gerados manualmente por uma plataforma externa, a qual não disponibiliza API para integração.

Nesta plataforma externa:

- é criado um usuário;
- esse usuário pode ser vinculado manualmente a um ou mais servidores de conteúdo;
- cada servidor gera um endpoint M3U independente;
- cada endpoint representa o acesso ao conteúdo disponibilizado por aquele servidor.

A responsabilidade da Nebula é gerenciar esses endpoints, vinculando-os aos dispositivos autorizados e disponibilizando-os ao Nebula Player através do Nebula Core.

---

# Decisão

A Nebula Platform adotará um modelo baseado em **Servidores de Conteúdo**.

Cada Servidor representa uma origem de conteúdo.

Cada Servidor poderá possuir um ou mais Endpoints M3U.

Os Endpoints M3U serão cadastrados manualmente pelos administradores da plataforma.

O Nebula Core será responsável por distribuir aos dispositivos apenas os Endpoints M3U autorizados.

---

# Modelo Conceitual

```text
ContentProvider

        │

        ▼

ProviderAccount

        │

        ▼

Servidor 01 ───────────────► Endpoint M3U

Servidor 02 ───────────────► Endpoint M3U

Servidor 03 ───────────────► Endpoint M3U

        │

        ▼

Nebula Core

        │

        ▼

Device (Nebula Player)
```

---

# Responsabilidades

## Plataforma Externa

Responsável por:

- criar usuários;
- vincular usuários aos servidores;
- gerar endpoints M3U.

---

## Nebula Admin

Responsável por:

- cadastrar usuários externos;
- cadastrar servidores;
- cadastrar endpoints M3U;
- vincular endpoints aos dispositivos;
- gerenciar autorizações.

---

## Nebula Core

Responsável por:

- validar dispositivos;
- localizar endpoints autorizados;
- distribuir endpoints ao Nebula Player;
- registrar auditoria das distribuições.

---

## Nebula Player

Responsável por:

- solicitar os endpoints autorizados;
- reproduzir o conteúdo;
- nunca armazenar permanentemente os endpoints recebidos.

---

# Regras

- A Nebula nunca gera playlists M3U.
- A Nebula nunca altera playlists M3U.
- Todo endpoint M3U é originado por uma plataforma externa.
- Apenas administradores podem cadastrar endpoints M3U.
- Apenas o Nebula Core pode disponibilizar endpoints ao Nebula Player.
- O Nebula Player nunca possui conhecimento sobre a plataforma externa.
- O Nebula Player nunca armazena permanentemente endpoints M3U.

---

# Consequências

A entidade **Playlist** deixa de representar o núcleo do domínio.

O domínio passa a ser centrado em:

- Devices
- Servers
- M3U Endpoints
- External Users

O relacionamento entre Device e conteúdo deixa de ocorrer através de Playlists e passa a ocorrer através de Endpoints M3U autorizados.

---

# Benefícios

- Arquitetura compatível com o processo operacional existente.
- Separação entre plataforma externa e Nebula Platform.
- Possibilidade de múltiplos endpoints por dispositivo.
- Flexibilidade para suportar diferentes provedores de conteúdo no futuro.
- Facilidade para substituição da plataforma externa caso uma integração via API venha a existir futuramente.

---

# Impactos Arquiteturais

Esta decisão altera o domínio da Nebula Platform.

As próximas modelagens deverão considerar as seguintes entidades principais:

Users (Admins)

- Clients

- Devices

- ContentProviders

- ProviderAccounts

- Servers

- ContentEndpoint

- DeviceServerAccess

- Sessions

- Heartbeats

- Telemetry

- Logs

A entidade **Playlist** deixa de ser o elemento central do domínio e passa a ser representada pelos Endpoints M3U fornecidos por servidores externos.
