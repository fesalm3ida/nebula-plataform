# ADR-029 — Pagamentos de licença via Mercado Pago

- **Status:** Accepted
- **Data:** 2026-09-15
- **Versão:** Nebula Platform v1.0
- **Autores:** Nebula Team

---

# Contexto

Após o trial (ADR-027), o usuário precisa comprar a licença. É necessário cobrar
de forma segura, sem armazenar dados de cartão, e **conceder a licença
automaticamente** quando o pagamento é aprovado.

Público-alvo inicial: Brasil (Pix, cartão e boleto).

---

# Decisão

Integração com o **Mercado Pago (Checkout Pro)**, isolada por uma **porta**:

- `PaymentGateway` (aplicação): `create_checkout`, `get_payment`,
  `find_payment`, `find_merchant_order`;
- `MercadoPagoClient` (infraestrutura) — `POST /checkout/preferences`,
  `GET /v1/payments/{id}`, `GET /v1/payments/search`,
  `GET /merchant_orders/{id}`;
- `FakePaymentGateway` — desenvolvimento/testes **sem chave real** (usado
  automaticamente quando não há token configurado).

**Fluxo:**

1. `POST /me/purchase` cria um `Payment` (`PENDING`) e o checkout; devolve a URL
   de pagamento. O `external_reference` é o **nosso `payment_id`**.
2. O Mercado Pago notifica `POST /webhooks/mercadopago`. São aceitos **os dois
   formatos**:
   - `topic=payment` com `data.id` (id do pagamento);
   - `topic=merchant_order` com `id` (corpo **e/ou** query string) — é o formato
     que o Checkout Pro realmente envia.
3. O Core **consulta o provedor** (nunca confia só na notificação), localiza o
   `Payment` pelo `external_reference`, e se aprovado: **aprova o pagamento e
   concede a licença** ao Device (idempotente).
4. **`POST /me/payments/sync`** — confirmação **ativa**: consulta os pagamentos
   pendentes do Device. Serve de rede de segurança quando a notificação não
   chega (ex.: sem URL pública) e é chamada pelo portal ao abrir.

**Configuração (Core):** `MERCADOPAGO_ACCESS_TOKEN`
(`.secrets/mercadopago_access_token`, ignorado pelo git),
`MERCADOPAGO_NOTIFICATION_URL` (URL pública do webhook, ex.: túnel ngrok) e
`MERCADOPAGO_BACK_URL` (retorno do usuário após o pagamento).

**Regras do provedor aprendidas (documentadas para não repetir):**

- `auto_return` **exige** `back_urls.success` em **HTTPS**; com HTTP o Mercado
  Pago responde **400** `auto_return invalid. back_url.success must be defined`.
  Solução: enviar `auto_return` **apenas** quando a `back_url` for HTTPS.
- A notificação do Checkout Pro é de **`merchant_order`**, não de `payment`.

---

# Consequências

- Nenhum dado de cartão passa pelo Nebula (checkout hospedado).
- Dupla via de confirmação: **webhook** (automático) + **sync** (sob demanda),
  com a mesma regra de concessão — o sistema não fica preso se a notificação
  falhar.
- O webhook precisa de **URL pública**; em desenvolvimento usamos **ngrok**.
- O ambiente de testes usa **credenciais e contas de teste** do Mercado Pago
  (comprador de teste + cartões de teste), sem cobrança real.

---

# Alternativas consideradas

- **Stripe** — excelente para cartão internacional, menos aderente a Pix/boleto
  no Brasil.
- **Pagamento manual/aprovação pelo administrador** — simples, não escala.
- **Confiar apenas no webhook** — frágil em desenvolvimento e em falhas de
  entrega; motivou o `sync`.
- **Conceder a licença pela URL de retorno (`back_urls`)** — o usuário poderia
  forjar a confirmação; a licença só é concedida após consulta ao provedor.
