# ADR-014 — Supported Python Version

- **Status:** Accepted
- **Date:** 2026-07-11
- **Deciders:** Nebula Architecture Team

---

## Context

The Nebula Core is developed primarily on Linux (Ubuntu LTS) through WSL and is intended to be easily reproducible by any contributor.

Although newer Python releases introduce useful language features, they are not always available by default on long-term support (LTS) Linux distributions.

During development, an incompatibility was identified when using the `datetime.UTC` constant, which is only available starting from Python 3.11.

The project must prioritize stability, portability and ease of onboarding over access to the newest language features.

---

## Decision

The Nebula Platform officially supports:

- **Python 3.10 or newer**

Until a future architectural review determines otherwise, the codebase **must avoid language features that require Python 3.11+** whenever an equivalent solution exists.

Example:

Preferred:

```python
from datetime import datetime, timezone

datetime.now(timezone.utc)
```

Avoid:

```python
from datetime import UTC, datetime

datetime.now(UTC)
```

---

## Rationale

This decision provides:

- Compatibility with Ubuntu 22.04 LTS.
- Compatibility with WSL default installations.
- Lower onboarding friction for contributors.
- Better compatibility with CI/CD environments.
- Stable ecosystem support for FastAPI, SQLAlchemy and Alembic.

The architectural benefits of Python 3.11+ do not currently justify reducing platform compatibility.

---

## Consequences

### Positive

- Broader compatibility across development environments.
- Reduced setup complexity.
- Predictable runtime behavior.
- Fewer environment-related issues.

### Negative

- Some modern Python features cannot be used immediately.
- Minor syntactic improvements introduced in newer Python versions must wait until a future migration.

---

## Future Considerations

After the MVP reaches production readiness, the project may evaluate migration to Python 3.12+.

Such migration shall occur only after:

- all CI pipelines are updated;
- deployment environments support the target version;
- compatibility testing is completed.

A future ADR will supersede this decision if migration becomes beneficial.
