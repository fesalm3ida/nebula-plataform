# ADR-016 — Session Heartbeat and Presence Model

- **Status:** Accepted
- **Data:** 2026-07-12
- **Autor:** Nebula Software House
- **Decisores:** Equipe Nebula
- **Relacionado:** ADR-001 (Stateless Player)

---

# Contexto

Atualmente uma `Session` representa uma conexão autenticada entre um Device e o Nebula Core.

A entidade possui as seguintes informações:

- session_id
- device_id
- started_at
- expires_at
- ended_at
- status

Embora essas informações permitam controlar o ciclo de vida da sessão, elas não permitem determinar se o dispositivo continua efetivamente conectado.

Para suportar monitoramento em tempo real, telemetria e detecção automática de desconexões, será introduzido o conceito de **Presence** através de Heartbeats enviados periodicamente pelo Nebula Player.

---

# Problema

Sem um mecanismo de Heartbeat, o Nebula Core consegue apenas determinar:

- quando uma sessão foi criada;
- quando foi encerrada explicitamente;
- quando expirou.

O servidor não consegue detectar eventos como:

- perda de conexão;
- desligamento inesperado do dispositivo;
- encerramento forçado do aplicativo;
- travamentos;
- falhas de rede.

Consequentemente, sessões podem permanecer ativas mesmo sem existir um Player conectado.

---

# Decisão

A entidade `Session` passa a possuir um novo atributo:

```python
last_seen: datetime
```

Durante a criação da sessão:

```text
last_seen = started_at
```

Sempre que um Heartbeat válido for recebido:

```text
last_seen = current_server_time
```

A entidade também passa a expor o método:

```python
touch()
```

Responsabilidade:

Atualizar o campo `last_seen` utilizando exclusivamente o relógio do servidor.

---

# Fluxo Arquitetural

```text
Nebula Player
        │
        │ POST /sessions/{id}/heartbeat
        ▼
FastAPI
        ▼
HeartbeatUseCase
        ▼
Session.touch()
        ▼
SessionRepository.save()
        ▼
Nebula Monitor
```

---

# Responsabilidades

## Session

Responsável apenas por manter seu próprio estado.

Conhece:

- started_at
- last_seen
- expires_at
- ended_at
- status

Não conhece:

- HTTP
- FastAPI
- Heartbeat
- Banco de Dados
- Telemetria

---

## HeartbeatUseCase

Será responsável por:

- localizar a Session;
- validar seu estado;
- executar `touch()`;
- persistir a alteração.

---

## Nebula Monitor

Consumirá `last_seen` para calcular:

- disponibilidade;
- uptime;
- sessões órfãs;
- desconexões;
- métricas operacionais.

---

# Timeout

Uma Session será considerada inativa quando:

```text
current_time - last_seen > timeout
```

A política de timeout não pertence à entidade.

Ela será implementada futuramente em um serviço de aplicação.

---

# Benefícios

Esta decisão permite:

- detectar desconexões automaticamente;
- medir presença em tempo real;
- alimentar dashboards;
- produzir métricas de disponibilidade;
- suportar Heartbeats de milhares de dispositivos;
- preparar o Nebula Monitor.

---

# Consequências

A entidade `Session` deixa de representar apenas autenticação.

Ela passa a representar também a presença do dispositivo dentro do ecossistema Nebula.

Essa decisão será utilizada por:

- Nebula Core
- Nebula Player
- Nebula Monitor
- Nebula Admin

---

# Alternativas Consideradas

## Utilizar apenas `expires_at`

Rejeitada.

Não permite saber se o dispositivo continua conectado durante a validade da sessão.

---

## Atualizar apenas o JWT

Rejeitada.

O JWT representa autenticação.

Não representa presença.

---

## Heartbeat armazenado apenas em memória

Rejeitada.

Perderia o estado após reinicialização do Core.

---

# Compatibilidade

Esta decisão é compatível com:

- ADR-001 — Stateless Player

Não introduz incompatibilidades arquiteturais.

---

# Implementação

- Adicionar `last_seen` à entidade `Session`;
- Inicializar `last_seen = started_at`;
- Implementar `Session.touch()`;
- Atualizar `StartSessionUseCase`;
- Atualizar `StartSessionResponse`;
- Criar `HeartbeatUseCase`;
- Criar endpoint `POST /sessions/{id}/heartbeat`.
