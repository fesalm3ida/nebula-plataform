# ADR-025 — ContentEntitlement

- **Status:** Accepted
- **Data:** 2026-09-06
- **Versão:** Nebula Core v0.4.x
- **Autores:** Nebula Team

---

# Contexto

O domínio utilizava, de forma provisória, o termo **DeviceContentAuthorization**
para representar o vínculo entre um Device e os pontos de acesso ao conteúdo
(RFC-002). O mercado de streaming (OTT, DRM) utiliza o conceito de
**Entitlement** para representar o direito de um dispositivo ou cliente de
consumir determinado conteúdo.

---

# Decisão

Adotar **ContentEntitlement** como a terminologia/modelo autoritativo para o
direito de acesso de um Device (ou Cliente) a uma fonte de conteúdo.

Um `ContentEntitlement` representa o **direito de acesso**, e a forma concreta
de transporte desse direito é uma implementação especializada. No escopo atual:

- **`PlaylistAssignment`** (ADR-021) é a implementação concreta de um
  `ContentEntitlement` específico: o direito de um Device a uma `Playlist`
  (fonte de conteúdo).
- O termo `DeviceContentAuthorization` é **descontinuado** e passa a ser
  substituído por `ContentEntitlement` no vocabulário do domínio.

A associação permanece intermediada (Device → Entitlement → Fonte de conteúdo),
preservando a evolução prevista na ADR-021 (múltiplos perfis, múltiplas
Playlists, associação por cliente, políticas administrativas).

---

# Modelo Conceitual

```
Device
   │
   ▼
ContentEntitlement  (direito de acesso)
   │
   ├── PlaylistAssignment  (implementação atual: fonte = Playlist)
   └── (futuro: Xtream / Stalker / outros)
```

---

# Consequências

## Benefícios

- Nomenclatura aderente ao mercado (Entitlement).
- Base para múltiplos tipos de direito de acesso.
- Reaproveitamento da associação intermediária da ADR-021.

## Trade-offs

- Exige renomear a terminologia em documentos existentes.
- PlaylistAssignment passa a ser entendido como uma implementação concreta.

# Estado

**Accepted**

Esta decisão resolve o RFC-002 e adota `ContentEntitlement` como modelo
autoritativo de direito de acesso.
