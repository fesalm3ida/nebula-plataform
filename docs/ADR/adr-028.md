# ADR-028 — Portal do usuário (MAC + código) e administrador em URL secreta

- **Status:** Accepted
- **Data:** 2026-09-15
- **Versão:** Nebula Platform v1.0
- **Autores:** Nebula Team

---

# Contexto

Pela **ADR-021**, as playlists eram cadastradas exclusivamente pelo
administrador. O modelo de negócio, porém, exige **autoatendimento**: o dono do
aparelho ativa o Device e cadastra a própria lista, como em players comerciais
(ex.: Ibo Player: *"Login to add your playlist"* com **MAC Address + Device
Key**).

O `DeviceKey` do Nebula é um token de 32+ caracteres (segredo do app),
impraticável de digitar no site.

---

# Decisão

1. **Identificação pública + código curto.** Cada Device recebe, no registro,
   um **`ActivationCode`** de **6 dígitos** (value object próprio), exibido pelo
   Player. A `DeviceKey` continua sendo o segredo exclusivo do app.
2. **Login do usuário:** `POST /auth/portal` com `mac_address` +
   `activation_code` devolve um **token do Device**. Diferente da autenticação
   do app, **aceita Device pendente** (o usuário entra justamente para ativar);
   rejeita revogados.
3. **O usuário cadastra a própria lista:** `GET /me/playlist` e
   `POST /me/playlist` (cria a Playlist e a associa ao Device dele, revogando a
   anterior). Isso **revisa a ADR-021**, que passa a valer para o administrador.
4. **O administrador continua existindo**, com login próprio (e-mail + senha),
   acessível por uma **URL secreta** (`http://host:3000/#/<ADMIN_PATH>`),
   configurável por `--dart-define=ADMIN_PATH=...`. O usuário não a conhece.
5. **Player:** ao instalar, exibe **MAC Address + código de ativação** (sem QR
   Code, por ora) e verifica a ativação a cada 10 s, indo ao menu quando o
   Device é ativado.
6. **MAC:** o Android oculta o MAC real desde o Android 6; o app gera e
   persiste um **pseudo-MAC** localmente administrado (`02:...`), estável por
   instalação.

---

# Consequências

- Fluxo do usuário: instala → vê MAC + código → entra no site → **ativa**
  (trial de 7 dias) → cadastra a lista → o app entra no menu.
- O portal passa a ter **dois acessos** no mesmo app Flutter Web: usuário (raiz)
  e administrador (URL secreta).
- A **URL secreta é obscuridade**, não segurança: o controle real do
  administrador é o JWT do BFF. Em produção, recomenda-se restringir por rede
  (VPN/allowlist) além do segredo.
- O código de 6 dígitos é um segundo fator fraco (10⁶) combinado ao MAC; o
  risco é aceitável para ativação e pode evoluir para QR Code/limite de
  tentativas.

---

# Alternativas consideradas

- **Login com a DeviceKey (32+ caracteres)** — mais seguro, péssimo de digitar.
- **Código alfanumérico longo** — melhor entropia, pior usabilidade.
- **Cadastro com e-mail/senha do usuário** — exigiria gestão de contas,
  recuperação de senha e verificação, ampliando muito o escopo.
- **QR Code no app** — melhor usabilidade; adiado (o layout atual exibe os
  dados de forma legível e copiável).
