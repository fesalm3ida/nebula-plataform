# ADR-017 — Persistência PostgreSQL com SQLAlchemy e Alembic

- **Status:** Aceita
- **Data:** 2026-07-12
- **Autor:** Nebula Software House
- **Decisores:** Equipe Nebula
- **Versão:** First Light
- **Relacionadas:** ADR-012, ADR-013, ADR-015, ADR-016

---

## Contexto

O Nebula Core atualmente utiliza implementações de repositório em memória:

- `InMemoryDeviceRepository`;
- `InMemorySessionRepository`.

Essas implementações permitiram validar o domínio, os casos de uso e os fluxos HTTP sem introduzir dependência prematura de banco de dados.

Entretanto, todos os dados são perdidos quando o processo do Core é reiniciado.

A evolução da plataforma exige persistência durável para:

- Devices registrados;
- credenciais emitidas;
- status dos Devices;
- Sessions;
- timestamps de presença;
- encerramentos e expirações;
- futura telemetria e auditoria.

---

## Problema

Como persistir os dados do Nebula Core de forma durável sem acoplar o domínio e os casos de uso a uma tecnologia específica de banco de dados?

---

## Decisão

O Nebula Core utilizará:

- **PostgreSQL** como banco de dados relacional principal;
- **SQLAlchemy** como toolkit de persistência e mapeamento objeto-relacional;
- **Alembic** para controle de migrations;
- **psycopg** como driver de conexão com PostgreSQL.

As interfaces de repositório continuarão pertencendo ao domínio.

As implementações concretas baseadas em PostgreSQL pertencerão à camada de infraestrutura.
