ADR-012 — Critério para transformar valores enumerados em entidades
Status

Aceito

Contexto

Durante a modelagem lógica do Nebula Player, identificamos diversos atributos classificatórios, como:

EventType
LogLevel
Platform
AdministrativeStatus
OperationalState

Precisávamos estabelecer um critério arquitetural para decidir quando um valor enumerado deveria permanecer como um domínio enumerado (Enum) e quando deveria evoluir para uma entidade própria.

Sem esse critério, o projeto correria dois riscos:

transformar todo Enum em tabela (overengineering);
manter valores de negócio importantes como strings soltas (submodelagem).
Decisão

Nem todo valor enumerado será modelado como entidade.

Um valor classificatório deverá ser promovido para uma entidade quando atender a um ou mais dos seguintes critérios:

puder ser administrado pela plataforma;
puder evoluir sem alteração de código;
possuir metadados próprios;
for utilizado em filtros, dashboards ou relatórios;
representar conhecimento de negócio;
puder ser ativado ou desativado;
possuir regras próprias de domínio.

Caso contrário, permanecerá como um domínio enumerado.

Aplicação Inicial
Serão entidades
EventType
LogLevel
Permanecerão como Enum
Platform
AdministrativeStatus
OperationalState
Consequências
Benefícios
elimina strings livres;
melhora a integridade referencial;
facilita dashboards;
permite evolução do domínio sem alterar código;
cria um critério arquitetural objetivo para futuras modelagens.
Custos
aumenta discretamente o número de entidades do domínio;
exige gerenciamento dessas entidades pelo Nebula Core.
Observações

Esta ADR define um princípio de modelagem para toda a Nebula Platform, não apenas para o Nebula Player.

Novas entidades classificatórias deverão seguir este critério antes de serem adicionadas ao domínio.
