# Entidade: Log

## Descrição

Log representa um registro técnico gerado durante uma Session do Nebula Player.

Seu objetivo é auxiliar diagnóstico, investigação de falhas, suporte técnico e análise de problemas durante a execução do Player.

Log não representa comportamento do usuário.

Log não representa métrica de qualidade.

Log não representa autorização.

Log representa informação técnica sobre a execução do Player.

---

## Atributos

| Atributo | Obrigatório | Único | Observação |
|---|---:|---:|---|
| LogID | Sim | Sim | Identificador lógico do Log. |
| SessionID | Sim | Não | Session à qual o Log pertence. |
| LogLevelID | Sim | Não | Nível de severidade associado ao Log. |
| Message | Sim | Não | Mensagem técnica registrada. |
| Context | Não | Não | Dados técnicos adicionais relacionados ao Log. |
| CreatedAt | Sim | Não | Data de persistência do registro. |

---

## Níveis Permitidos

| Level | Descrição |
|---|---|
| Debug | Informação detalhada para diagnóstico durante desenvolvimento ou investigação. |
| Info | Informação operacional comum. |
| Warning | Situação inesperada que não interrompe necessariamente a execução. |
| Error | Erro que afeta alguma operação do Player. |
| Critical | Falha grave que pode comprometer a execução da Session. |

---

## Relacionamentos

| Origem | Cardinalidade | Destino | Descrição |
|---|---|---|---|
| Session | 1:N | Log | Uma Session pode gerar diversos Logs. |
| LogLevel | 1:N | Log | Um LogLevel pode classificar diversos Logs. |
---

## Regras Importantes

- Todo Log pertence exatamente a uma Session.
- Logs são imutáveis após registrados.
- Logs nunca substituem TelemetryEvents.
- Logs nunca representam Heartbeats.
- Logs nunca representam autorização.
- Logs não devem conter credenciais.
- Logs não devem conter tokens.
- Logs não devem conter ContentEndpoints completos.
- Logs não devem conter dados sensíveis.
- Logs podem ser utilizados pelo suporte técnico para investigação de falhas.
